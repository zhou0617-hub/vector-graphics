# 问题排查记录

本文档记录开发过程中实际遇到并解决的问题。

## 一、Docker 相关问题

### 问题 1：docker 命令找不到

**现象**

```
zsh: command not found: docker
```

**原因**

Docker Desktop 尚未安装完成，或安装后没有把 bin 目录加入 PATH。

**排查**

```bash
ls /Applications | grep -i docker
which docker || echo "docker not in PATH"
```

**解决**

1. 确认 `/Applications/Docker.app` 存在
2. 打开 Docker Desktop，等菜单栏鲸鱼图标稳定
3. 如果仍未识别，把 bin 目录加入 PATH：

```bash
echo 'export PATH="$PATH:/Applications/Docker.app/Contents/Resources/bin"' >> ~/.zshrc
source ~/.zshrc
```

## 二、Docker Compose 相关问题

### 问题 2：docker compose 命令不存在

**现象**

```
docker: unknown command: docker compose
```

**原因**

Docker Desktop 未自带 Compose V2 插件，系统里也没有单独安装。

**排查**

```bash
which docker
docker --version
docker compose version
```

**解决**

通过 Homebrew 安装：

```bash
brew install docker-compose
```

安装完成后，需要在 `~/.docker/config.json` 中加入插件路径：

```json
{
  "cliPluginsExtraDirs": [
    "/opt/homebrew/lib/docker/cli-plugins"
  ]
}
```

如果该文件已存在（可能含 `auths`、`credsStore` 等字段），只追加 `cliPluginsExtraDirs` 字段，不要覆盖原内容。

**验证**

```bash
docker compose version
```

输出类似 `Docker Compose version v5.5.1`。

## 三、Docker Desktop 启动失败

### 问题 3：Docker Desktop is unable to start

**现象**

执行 `docker compose up -d` 时报错：

```
✘ Image rabbitmq:3-management-alpine Error request returned 500 Internal...
request returned 500 Internal Server Error for API route
Error response from daemon: Docker Desktop is unable to start
```

**原因**

Docker 的虚拟机进程卡死，或虚拟磁盘文件损坏。

**解决**

1. 菜单栏 Docker 图标 → Quit Docker Desktop
2. 清理残留进程：

```bash
sudo killall Docker com.docker.backend com.docker.vmnetd 2>/dev/null || true
```

3. **重启 Mac**（这一步很关键，用于清理虚拟机框架状态）
4. 重新打开 Docker Desktop，等菜单栏鲸鱼图标稳定
5. 验证：

```bash
docker info
```

能看到 `Server Version` 就说明引擎正常。

**如果重启后仍失败**，删除虚拟磁盘文件（会清空已下载的镜像，需要重新拉取）：

```bash
rm -rf ~/Library/Containers/com.docker.docker/Data/vms/0/data/Docker.raw
```

然后重新打开 Docker Desktop。

## 四、端口占用

### 问题 4：3306 端口已被占用

**现象**

`docker compose up -d` 时报错：

```
Error response from daemon: ports are not available: 
exposing port TCP 0.0.0.0:3306 -> 127.0.0.1:0: 
listen tcp 0.0.0.0:3306: bind: address already in use
```

**原因**

开发机上用 Homebrew 装过 MySQL，正在后台运行，占用了 3306。

**排查**

```bash
lsof -i :3306
brew services list | grep mysql
```

输出显示 `mysqld` 进程和 `mysql started`。

**解决**

停掉 Homebrew 的 MySQL：

```bash
brew services stop mysql
```

再次检查端口：

```bash
lsof -i :3306
```

无输出说明端口已释放。然后重新启动 Docker 容器。

**备选方案**

如果不想停本机 MySQL，可以改 Docker 的端口映射。修改 `docker-compose.yml`：

```yaml
mysql:
  ports:
    - "3307:3306"
```

同时修改 `application-dev.yml` 里的连接地址改为 `localhost:3307`。

## 五、Maven / Java 相关问题

### 问题 5：Lombok 注解不生效

**现象**

编译时报错：

```
[ERROR] COMPILATION ERROR : 
[ERROR] 找不到符号
  符号:   变量 log
  位置: 类 com.svgplatform.common.exception.GlobalExceptionHandler
[ERROR] 找不到符号
  符号:   方法 getCode()
  位置: 类型为com.svgplatform.common.exception.BusinessException的变量 e
[ERROR] 无法推断com.svgplatform.common.response.ApiResponse<>的类型参数
```

**原因**

Java 21 + Spring Boot 3.3.x 组合下，Lombok 需要显式声明为注解处理器，仅作为依赖引入不够。

**解决**

在 `pom.xml` 的 `maven-compiler-plugin` 里配置 `annotationProcessorPaths`：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <source>21</source>
        <target>21</target>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>${lombok.version}</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

同时 Lombok 依赖改为 `provided`：

```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <version>${lombok.version}</version>
    <scope>provided</scope>
</dependency>
```

### 问题 6：TypeTag :: UNKNOWN

**现象**

注解处理器配置好后，重新编译仍失败：

```
[ERROR] Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin:3.13.0:compile
Fatal error compiling: java.lang.ExceptionInInitializerError: 
com.sun.tools.javac.code.TypeTag :: UNKNOWN
```

**原因**

Lombok 1.18.34 与 Java 21 不兼容。

**解决**

升级 Lombok 到 1.18.42（或更高）：

```bash
cd backend
sed -i '' 's/1.18.34/1.18.42/' pom.xml
rm -rf ~/.m2/repository/org/projectlombok/lombok/1.18.34
./mvnw clean compile
```

**注意**：Lombok 版本必须 >= 1.18.42 才能兼容 Java 21。

### 问题 7：Unsupported character encoding 'utf8mb4'

**现象**

Spring Boot 启动时 Flyway 报错：

```
org.springframework.beans.factory.BeanCreationException: Error creating bean with name 'flywayInitializer'
Caused by: org.flywaydb.core.internal.exception.FlywaySqlException: 
Unable to obtain connection from database: Unsupported character encoding 'utf8mb4'
Caused by: java.io.UnsupportedEncodingException: utf8mb4
```

**原因**

JDBC URL 的 `characterEncoding` 参数是 **Java 编码名**，不是 MySQL 字符集名。Java 不认 `utf8mb4`，只认 `UTF-8`。`utf8mb4` 是 MySQL 服务端的字符集名，两者不能混用。

**解决**

修改 `application-dev.yml`：

```yaml
url: jdbc:mysql://localhost:3306/vector_graphics?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=UTF-8&allowPublicKeyRetrieval=true
```

注意是 `characterEncoding=UTF-8`（大写，带横线），不是 `utf8mb4`。

MySQL 表本身的字符集仍然是 `utf8mb4`，由 Flyway 迁移脚本里的 `DEFAULT CHARSET=utf8mb4` 保证。

## 六、Spring Security 相关问题

### 问题 8：未登录返回 403 而非 401

**现象**

不带 token 访问 `/api/users/me`，返回：

```json
{"timestamp":"2026-09-22T08:35:19.245+00:00","status":403,"error":"Forbidden","path":"/api/users/me"}
```

**原因**

Spring Security 默认对未认证请求返回 403（Forbidden），且响应体是 Spring 默认的 JSON 结构，不是自定义的 `{code, message, data}` 格式。

**解决**

自定义两个处理器。

`RestAuthenticationEntryPoint`：处理未认证（401）。

```java
@Component
public class RestAuthenticationEntryPoint implements AuthenticationEntryPoint {
    private final ObjectMapper objectMapper = new ObjectMapper();

    @Override
    public void commence(HttpServletRequest request, HttpServletResponse response,
                         AuthenticationException authException) throws IOException {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());
        ApiResponse<Void> body = ApiResponse.error(ErrorCode.UNAUTHORIZED, "未登录或登录已过期");
        response.getWriter().write(objectMapper.writeValueAsString(body));
    }
}
```

`RestAccessDeniedHandler`：处理无权限（403）。

```java
@Component
public class RestAccessDeniedHandler implements AccessDeniedHandler {
    private final ObjectMapper objectMapper = new ObjectMapper();

    @Override
    public void handle(HttpServletRequest request, HttpServletResponse response,
                       AccessDeniedException accessDeniedException) throws IOException {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setCharacterEncoding(StandardCharsets.UTF_8.name());
        ApiResponse<Void> body = ApiResponse.error(ErrorCode.FORBIDDEN, "没有权限");
        response.getWriter().write(objectMapper.writeValueAsString(body));
    }
}
```

`SecurityConfig` 中注册：

```java
.exceptionHandling(ex -> ex
    .authenticationEntryPoint(restAuthenticationEntryPoint)
    .accessDeniedHandler(restAccessDeniedHandler)
)
```

**修复后**

- 未登录访问受保护接口 → 返回 `{"code":401,"message":"未登录或登录已过期","data":null}`
- 无权限访问 → 返回 `{"code":403,"message":"没有权限","data":null}`

## 七、矢量化调用相关问题

### 问题 9：DataBufferLimitException 262144（关键问题）

**现象**

小图转换成功，大图（例如 1.5MB 的截图）转换失败。日志：

```
ERROR c.s.i.vectorizer.VectorizerClient : 调用矢量化服务失败
org.springframework.web.reactive.function.client.WebClientResponseException: 
200 OK from POST http://localhost:8000/api/vectorize, 
but response failed with cause: 
org.springframework.core.io.buffer.DataBufferLimitException: 
Exceeded limit on max bytes to buffer : 262144
```

数据库日志显示：

```
==>  Preparing: UPDATE conversions SET ... status=?, error_message=? WHERE id=?
==> Parameters: ..., failed(String), 矢量化服务不可用(String), ...
```

Python 服务端日志显示 `POST /api/vectorize HTTP/1.1" 200 OK`，说明 Python 已经成功处理并返回结果，但 Java 端读取响应时被截断。

**原因**

Spring WebClient 默认最大内存缓冲 **256 KB**（262144 字节）。小图矢量化后的 SVG 不到 256KB，能成功；大图矢量化后的 SVG 有几 MB，超过限制，Java 端读取时直接抛异常。

**不是 Python 的问题**，Python 已经正常返回了 200。

**解决**

在 `VectorizerClient` 中显式配置缓冲上限：

```java
private static final int MAX_IN_MEMORY_SIZE = 50 * 1024 * 1024;  // 50MB

private WebClient buildClient() {
    ExchangeStrategies strategies = ExchangeStrategies.builder()
            .codecs(c -> c.defaultCodecs().maxInMemorySize(MAX_IN_MEMORY_SIZE))
            .build();

    return WebClient.builder()
            .baseUrl(props.getBaseUrl())
            .exchangeStrategies(strategies)
            .build();
}
```

同时在 `application.yml` 加全局配置：

```yaml
spring:
  codec:
    max-in-memory-size: 50MB
```

**验证方式**

用生成的大图（例如 1.5MB 的截图）重新测试，转换应该成功返回。

## 八、无害警告（无需处理）

以下警告在开发过程中出现，但**不影响功能**。

### 警告 1：sun.misc.Unsafe 相关警告

```
WARNING: A terminally deprecated method in sun.misc.Unsafe has been called
WARNING: sun.misc.Unsafe::allocateMemory has been called by 
io.netty.util.internal.PlatformDependent0$2
```

**原因**：Java 21+ 对旧 API 的弃用警告，Netty 内部使用。

**处理**：忽略。

### 警告 2：MacOSDnsServerAddressStreamProvider 加载失败

```
WARN i.n.r.d.DnsServerAddressStreamProviders : 
Unable to load io.netty.resolver.dns.macos.MacOSDnsServerAddressStreamProvider, 
fallback to system defaults. This may result in incorrect DNS resolutions on MacOS.
```

**原因**：macOS 上 Netty 缺少原生 DNS 解析库。

**影响**：无害。项目连接的是 `localhost`，不走 DNS 解析。

**如需消除**（不推荐，会引入额外体积）：

```xml
<dependency>
    <groupId>io.netty</groupId>
    <artifactId>netty-resolver-dns-native-macos</artifactId>
    <classifier>osx-aarch_64</classifier>
</dependency>
```

'[com.svgplatform.modules.**.repository]' package
```

**原因**：Mapper 包下暂时没有 Mapper 接口。

**处理**：写完第一个 Mapper 后自动消失。无需处理。

### 警告 4：Using generated security password

```

**原因**：Spring Security 自动配置生成了默认用户密码。

**处理**：忽略。自定义的 `SecurityFilterChain` 已经生效，这个默认用户不会被使用。

### 警告 5：Maven Wrapper 的 Unsafe 警告

```

```

**原因**：Maven 依赖的 Guice 用了旧 API。

**处理**：忽略。

### 问题 17：刷新浏览器要求重新登录

**现象**

刷新页面（F5 或 Cmd+R），跳转到登录页。

**原因**

1. `RequireAuth` 的 useEffect 比 `Providers` 的 `hydrate()` 先跑，读到的 token 是 null
2. `user` 未持久化，每次刷新都要调用 `/api/users/me` 补全

**解决**

**1. auth-store 持久化 token 和 user**

```ts
const TOKEN_KEY = 'token';
const USER_KEY = 'user';

setAuth: (token, user) => {
  localStorage.setItem(TOKEN_KEY, token);
  localStorage.setItem(USER_KEY, JSON.stringify(user));
  set({ token, user });
},

hydrate: () => {
  const token = localStorage.getItem(TOKEN_KEY);
  const userStr = localStorage.getItem(USER_KEY);
  let user = null;
  if (userStr) {
    try { user = JSON.parse(userStr); } catch { user = null; }
  }
  set({ token: token || null, user, hydrated: true });
},
```

**2. RequireAuth 等 hydrated**

```tsx
export function RequireAuth({ children }: Props) {
  const token = useAuthStore((s) => s.token);
  const hydrated = useAuthStore((s) => s.hydrated);

  useEffect(() => {
    if (!hydrated) return;
    if (!token) {
      router.replace(`/login?redirect=${encodeURIComponent(pathname)}`);
    }
  }, [hydrated, token, router, pathname]);

  if (!hydrated || !token) {
    return <Loading />;
  }
  return <>{children}</>;
}
```

**3. client.ts 401 全局拦截**

```ts
if (json.code === 401) {
  localStorage.removeItem('token');
  localStorage.removeItem('user');
  const path = window.location.pathname;
  if (path !== '/login' && path !== '/register') {
    window.location.href = `/login?redirect=${encodeURIComponent(path)}`;
  }
  throw new ApiError(401, json.message || '登录已过期');
}
```

### 问题 18：跨域下载 SVG 时 download 属性失效

**现象**

点击"下载 SVG"按钮，浏览器直接打开 SVG 文件，而不是下载。

**原因**

`<a href download>` 在跨域时 `download` 属性被浏览器忽略。

**解决**

用 `fetch + blob`：

```ts
export async function downloadFile(url: string, filename: string): Promise<void> {
  const res = await fetch(url, { credentials: 'omit' });
  if (!res.ok) throw new Error(`下载失败 (${res.status})`);
  const blob = await res.blob();
  const blobUrl = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = blobUrl;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  setTimeout(() => URL.revokeObjectURL(blobUrl), 1000);
}
```

**应用位置**

- `app/(main)/tools/image-to-svg/page.tsx`
- `components/image-viewer.tsx`
- `app/(main)/my/files/page.tsx`

### 问题 19：Jackson 字符串长度超限

**现象**

转换较大的 JPG 时报"矢量化服务不可用"。

**真实错误**

```
com.fasterxml.jackson.core.exc.StreamConstraintsException: 
String value length (20051112) exceeds the maximum allowed 
(20000000, from StreamReadConstraints.getMaxStringLength())
```

**原因**

SVG 字符串 2000 万字符，超过 Jackson 默认字符串长度限制。

**两层限制**

| 限制 | 位置 | 默认 | 改成 |
|---|---|---|---|
| WebClient 缓冲 | ExchangeStrategies.maxInMemorySize | 256KB | 200MB |
| Jackson 字符串 | StreamReadConstraints.maxStringLength | 20MB | 200MB |

**解决**

```java
private static final int MAX_STRING_LENGTH = 200 * 1024 * 1024;

public VectorizerClient(VectorizerProperties props) {
    this.props = props;
    this.objectMapper = new ObjectMapper(
        JsonFactory.builder()
            .streamReadConstraints(
                StreamReadConstraints.builder()
                    .maxStringLength(MAX_STRING_LENGTH)
                    .build()
            )
            .build()
    );
}
```

**同步配置**

```yaml
spring:
  codec:
    max-in-memory-size: 200MB
```
