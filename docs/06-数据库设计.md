## 十四、表关系图

```
users ─┬─< files ─< conversions
       │
       ├─< posts ─┬─< post_files >─ files
       │          ├─< post_tags >─ tags
       │          ├─< comments
       │          ├─< likes
       │          └─< favorites
       │
       └─< reports
```

**关系说明**

- 一个用户可上传多个文件（`files.user_id → users.id`）
- 一个文件可有多次转换记录（`conversions.file_id → files.id`）
- 一个用户可发布多个作品（`posts.user_id → users.id`）
- 一个作品可包含多个文件（通过 `post_files` 多对多）
- 一个作品可有多个标签（通过 `post_tags` 多对多）
- 评论、点赞、收藏都关联到作品
- `likes` 和 `favorites` 用唯一索引保证不重复

**当前没有使用数据库外键约束**，依靠应用层保证一致性。

## 十五、常用查询

```sql
-- 查看所有表
SHOW TABLES;

DESC users;

DESC conversions;

-- 查看用户
SELECT id, email, username, role, status, created_at FROM users;

-- 查看某用户的文件
SELECT id, name, format, size, svg_url FROM files WHERE user_id = 1;

-- 查看转换成功率
SELECT status, COUNT(*) FROM conversions GROUP BY status;

-- 查看失败的转换记录
SELECT id, user_id, file_id, error_message, created_at 
FROM conversions 
WHERE status = 'failed' 
ORDER BY created_at DESC 
LIMIT 20;
```

## 十六、数据库迁移规范

**新增表或修改表结构时，不要手动改数据库**。步骤：

1. 在 `backend/src/main/resources/db/migration/` 下新建 SQL 文件，按版本递增命名，例如 `V2__add_post_views.sql`
2. 写入变更 SQL
3. 重启后端，Flyway 自动执行
4. 每次修改都有记录，可追溯

**版本命名规则**：`V{版本号}__{描述}.sql`

- 版本号必须是整数，从 1 开始
- 中间是两个下划线
- 描述用下划线分隔

**示例**

```sql
-- V2__add_post_views.sql
ALTER TABLE posts ADD COLUMN view_count INT NOT NULL DEFAULT 0 AFTER comment_count;
```

## 附录：2026-09-23 数据库变更操作指南

### 一、核心原则

永远不要手动改数据库。所有变更都通过 Flyway 迁移脚本完成。

### 二、新增字段的完整流程

以给 users 表加 nickname 字段为例。

#### 第 1 步：写迁移脚本

**位置**：`backend/src/main/resources/db/migration/`

**文件名**：`V2__add_nickname_to_users.sql`

```sql
ALTER TABLE users 
ADD COLUMN nickname VARCHAR(64) DEFAULT NULL 
COMMENT '昵称' 
AFTER username;
```

#### 第 2 步：修改 Java 实体

**文件**：`modules/user/entity/User.java`

```java
private String nickname;
```

MyBatis-Plus 自动做驼峰转换，`nickname` 字段自动映射数据库列 `nickname`。

#### 第 3 步：修改 DTO 和 Converter

**UserResponse.java**

```java
private String nickname;
```

**UserConverter.java**

```java
resp.setNickname(user.getNickname());
```

#### 第 4 步：重启后端

日志应显示：

```
Migrating schema `vector_graphics` to version "2 - add nickname to users"
Successfully applied 1 migration
```

#### 第 5 步：验证

```bash
docker exec -it vg-mysql mysql -uvg -pvg123456 vector_graphics -e "DESC users;"
```

### 三、Flyway 工作机制

```
后端启动
  ↓
检查 flyway_schema_history 表
  ↓
对比 classpath:db/migration/ 下的所有 V*.sql
  ↓
找到未执行过的 → 按版本号顺序执行
  ↓
执行成功 → 写入 flyway_schema_history
  ↓
继续启动
```

```

```

- V 大写
- 版本号递增
- 两个下划线
- 描述用下划线分隔

### 六、关键注意

**1. 已执行的脚本不要改**

Flyway 会校验 checksum，改动会报错：

```
Validate failed: Migration checksum mismatch for migration version 2
```

正确做法：新建 V3 做修正。

**2. 版本号必须递增**

不能 V1 → V3 → V2。

**3. 迁移失败的处理**

查看历史：

```bash
docker exec -it vg-mysql mysql -uvg -pvg123456 vector_graphics \
  -e "SELECT * FROM flyway_schema_history;"
```

如果 `success = 0`：

```sql
DELETE FROM flyway_schema_history WHERE version = '2';
```

重启后端，Flyway 重新执行 V2。

### 七、本地重置

**方式 A：清空数据库**

```bash
docker exec -it vg-mysql mysql -uvg -pvg123456 -e "
DROP DATABASE vector_graphics;

GRANT ALL PRIVILEGES ON vector_graphics.* TO 'vg'@'%';

"
```

重启后端，Flyway 从 V1 重新执行。

**方式 B：删 Docker 卷**

```bash
docker compose down -v

```

### 十、操作速查表

| 场景 | 操作 |
|---|---|
| 新增字段 | 新建 V{N}__add_xxx.sql + 改 Entity + 改 DTO/Converter + 重启 |
| 新增表 | 新建 V{N}__create_xxx.sql + 建 Entity/Mapper/Service/Controller + 重启 |
