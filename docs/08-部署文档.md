## 二、生产部署规划

**状态**：规划中，尚未实际部署。

以下是推荐的部署方案，实际执行时可根据需要调整。

### 2.1 服务拆分

| 服务 | 推荐平台 | 说明 |
|---|---|---|
| 前端 Next.js | Vercel | 零配置部署，自动 CDN |
| 后端 Spring Boot | Railway / Fly.io / 阿里云 ECS | 容器化部署 |
| 矢量化服务 FastAPI | Railway / Fly.io | 独立容器，CPU 即可 |
| MySQL | PlanetScale / AWS RDS / 阿里云 RDS | 托管数据库 |
| Redis | Upstash / 阿里云 Redis | 按量付费 |
| RabbitMQ | CloudAMQP / 阿里云 RabbitMQ | 托管队列 |
| 文件存储 | Cloudflare R2 / 阿里云 OSS | 对象存储 |

### 2.2 前端部署（Vercel）

**步骤**

1. 把 `frontend/` 推到 GitHub
2. 在 Vercel 导入该仓库
3. 配置环境变量：

```
NEXT_PUBLIC_API_BASE_URL=https://api.yourdomain.com
```

4. 部署

**注意**

- 前端通过 `NEXT_PUBLIC_API_BASE_URL` 访问后端，必须配置成生产后端的地址
- 后端 CORS 需要允许前端域名

### 2.3 后端部署（Railway / Fly.io）

**构建 Docker 镜像**

`backend/Dockerfile`：

```dockerfile
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY .mvn/ .mvn/
COPY mvnw pom.xml ./
RUN ./mvnw dependency:go-offline
COPY src/ src/
RUN ./mvnw clean package -DskipTests

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**环境变量**

生产环境必须配置：

| 变量 | 说明 |
|---|---|
| SPRING_PROFILES_ACTIVE | prod |
| SPRING_DATASOURCE_URL | 数据库连接 URL |
| SPRING_DATASOURCE_USERNAME | 数据库用户 |
| SPRING_DATASOURCE_PASSWORD | 数据库密码 |
| SPRING_DATA_REDIS_HOST | Redis 地址 |
| SPRING_DATA_REDIS_PORT | Redis 端口 |
| SPRING_RABBITMQ_HOST | RabbitMQ 地址 |
| SPRING_RABBITMQ_USERNAME | RabbitMQ 用户 |
| SPRING_RABBITMQ_PASSWORD | RabbitMQ 密码 |
| APP_JWT_SECRET | JWT 密钥（至少 32 字节随机字符串） |
| APP_VECTORIZER_BASE_URL | 矢量化服务地址 |
| APP_STORAGE_TYPE | r2 或 oss |

**创建 `application-prod.yml`**

```yaml
spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL}
    username: ${SPRING_DATASOURCE_USERNAME}
    password: ${SPRING_DATASOURCE_PASSWORD}
  data:
    redis:
      host: ${SPRING_DATA_REDIS_HOST}
      port: ${SPRING_DATA_REDIS_PORT}
  rabbitmq:
    host: ${SPRING_RABBITMQ_HOST}
    username: ${SPRING_RABBITMQ_USERNAME}
    password: ${SPRING_RABBITMQ_PASSWORD}
  codec:
    max-in-memory-size: 50MB

app:
  jwt:
    secret: ${APP_JWT_SECRET}
    expiration: 604800000
  vectorizer:
    base-url: ${APP_VECTORIZER_BASE_URL}
  storage:
    type: ${APP_STORAGE_TYPE}
    r2:
      account-id: ${R2_ACCOUNT_ID}
      access-key: ${R2_ACCESS_KEY}
      secret-key: ${R2_SECRET_KEY}
      bucket: ${R2_BUCKET}
      public-url: ${R2_PUBLIC_URL}
```

**部署**

- Railway：关联 GitHub 仓库，自动检测 Dockerfile 部署
- Fly.io：`fly launch` 生成配置后 `fly deploy`

### 2.4 矢量化服务部署

**Dockerfile**

`vectorizer/Dockerfile`：

```dockerfile
FROM python:3.11-slim

WORKDIR /app

RUN apt-get update && apt-get install -y \
    gcc \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ app/

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**注意**

- VTracer 是 CPU 推理，不需要 GPU
- 内存建议至少 512MB
- 无状态，可水平扩展

### 2.5 数据库迁移

**方案 A：Flyway 自动执行**

后端启动时 Flyway 自动执行迁移。`application-prod.yml` 里：

```yaml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
```

**方案 B：手动执行**

```bash
./mvnw flyway:migrate -Dflyway.url=... -Dflyway.user=... -Dflyway.password=...
```

**首次部署时**，如果目标数据库为空，Flyway 会从 V1 开始执行所有迁移脚本。

### 2.6 存储切换（本地 → R2）

当前使用 `LocalStorageService`，生产环境建议切换到 R2 或 OSS。

**新增 `R2StorageService`**

```java
@Service
@ConditionalOnProperty(name = "app.storage.type", havingValue = "r2")
public class R2StorageService implements StorageService {
    // 用 AWS S3 SDK 或 MinIO SDK 实现
    // R2 兼容 S3 协议
}
```

**配置切换**

```yaml
app:
  storage:
    type: r2  # 从 local 改为 r2
```

**说明**：`LocalStorageService` 上有 `@ConditionalOnProperty(name = "app.storage.type", havingValue = "local", matchIfMissing = true)`，所以只要 `type=r2`，它就不会被加载。

### 2.7 域名与 HTTPS

**前端**

- Vercel 自动分配 `xxx.vercel.app` 域名
- 可以绑定自定义域名，自动配 HTTPS

**后端**

- Railway / Fly.io 提供默认域名
- 建议绑定 `api.yourdomain.com`，用 Let's Encrypt 免费证书

**CORS 更新**

后端 `SecurityConfig` 里的 CORS 需要改成：

```java
config.setAllowedOrigins(List.of(
    "https://yourdomain.com",
    "https://www.yourdomain.com"
));
```

## 三、生产环境检查清单

部署前确认：

- [ ] `app.jwt.secret` 改为 32 字节以上随机字符串，**不要用开发时的默认值**
- [ ] 数据库密码改为强密码
- [ ] `application-prod.yml` 里的数据库、Redis、RabbitMQ 都指向生产实例
- [ ] 文件存储切换到 R2 或 OSS，实现对应的 `StorageService`
- [ ] CORS 只允许前端域名，不用 `*`
- [ ] 关闭 Swagger（或加访问密码）
- [ ] 配置日志收集（如 Sentry）
- [ ] 配置数据库自动备份
- [ ] 配置 HTTPS
- [ ] 前端 `NEXT_PUBLIC_API_BASE_URL` 指向生产后端
- [ ] 测试完整链路：注册 → 登录 → 上传 → 转换 → 下载

## 五、本地 Docker 全栈（可选）

如果想把三个服务也 Docker 化，在根目录建 `docker-compose.full.yml`：

```yaml
services:
  mysql:
    # 同 docker-compose.yml
  redis:
    # 同 docker-compose.yml
  rabbitmq:
    # 同 docker-compose.yml

  vectorizer:
    build: ./vectorizer
    ports:
      - "8000:8000"
    depends_on:
      - mysql

  backend:
    build: ./backend
    ports:
      - "8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: dev
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/vector_graphics?...
      APP_VECTORIZER_BASE_URL: http://vectorizer:8000
    depends_on:
      mysql:
        condition: service_healthy

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    environment:
      NEXT_PUBLIC_API_BASE_URL: http://localhost:8080
    depends_on:
      - backend
```

**注意**：这种方案适合演示，不适合日常开发（改代码要重新构建镜像）。

## 六、回滚策略

### 后端回滚

Railway / Fly.io 都支持回滚到之前的部署版本，在控制台一键操作。

### 数据库回滚

Flyway 社区版**不支持自动回滚**。如果需要回滚：

**方案 A：手动执行反向 SQL**

```sql
-- 比如 V2 加了字段，写一个反向 SQL 删掉
ALTER TABLE posts DROP COLUMN view_count;
```

**方案 B：从备份恢复**

```bash
mysql -h prod-host -u user -p database < backup_before_deploy.sql
```

**建议**：每次部署前先备份数据库。

### 三、引擎 GPU 适配

`esrgan-service/app/services/engines/realesrgan_engine.py`：

```python
import torch

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
use_half = device.type == "cuda"

self._upsampler = RealESRGANer(
    scale=cfg["scale"],
    model_path=cfg["path"],
    model=cfg["arch"],
    tile=0 if device.type == "cuda" else 400,
    tile_pad=10,
    pre_pad=0,
    half=use_half,
    device=device,
)
```

**关键参数**

| 参数 | CPU | GPU |
|---|---|---|
| tile | 400（分块） | 0（不分块） |
| half | False | True（半精度） |
| device | cpu | cuda |

### 六、Docker 部署

`esrgan-service/Dockerfile`：

```dockerfile
FROM pytorch/pytorch:2.1.0-cuda12.1-cudnn8-runtime

WORKDIR /app

RUN apt-get update && apt-get install -y \
    libgl1-mesa-glx libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt \
    -i https://pypi.tuna.tsinghua.edu.cn/simple

COPY app/ app/
COPY weights/ weights/

EXPOSE 8001
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8001"]
```

**注意**

- 基础镜像要选 CUDA 版本
- 权重文件需要 COPY 进镜像（或挂载 volume）
