# 开发规范

## 一、跨平台原则（核心）

项目必须同时支持 macOS 和 Windows，不因操作系统不同导致开发困难。

这条原则优先于一切开发便利性。

### 1.1 路径处理

绝对禁止硬编码路径分隔符。

| 语言 | 正确 | 错误 |
|---|---|---|
| Java | `Paths.get("data", "uploads")` | `"data\\uploads"` |
| Python | `Path("data") / "uploads"` | `"data\\uploads"` |
| Node.js | `path.join('data', 'uploads')` | `'data/uploads'` |
| 配置文件 | `./data/uploads`（运行时解析） | 绝对路径 |

### 1.2 换行符

统一使用 LF。`.gitattributes` 已强制 `eol=lf`。

### 1.3 文件名与目录名

统一使用小写 + 中划线。

原因：Linux 文件系统大小写敏感，macOS 和 Windows 不敏感。混用会导致"本地能跑，部署就崩"。

| 正确 | 错误 |
|---|---|
| `image-to-svg` | `ImageToSvg` |
| `user-profile` | `user_profile` |
| `my-files` | `MyFiles` |

### 1.4 Shell 脚本

不允许把 `.sh` 或 `.bat` 作为唯一入口。所有跨平台脚本用 Node.js 编写。

| 错误 | 正确 |
|---|---|
| `scripts/deploy.sh` | `scripts/deploy.js` |
| `scripts/start.bat` | `scripts/start.js` |

### 1.5 命令差异处理

用 `os.platform()` 判断：

```js
const os = require('os');
const isWindows = os.platform() === 'win32';

// Maven Wrapper
const mvnCmd = isWindows ? 'mvnw.cmd' : './mvnw';

// spawn 是否需要 shell
spawn(cmd, args, { shell: isWindows });

// 等待命令
const waitCmd = isWindows ? 'timeout /t 10 /nobreak > nul' : 'sleep 10';
```

### 1.6 Python 虚拟环境

自动检测路径，不硬编码：

```js
function findVenvPython(baseDir) {
  const subDirs = isWindows ? ['Scripts'] : ['bin'];
  const names = isWindows ? ['python.exe', 'python3.exe'] : ['python', 'python3'];
  for (const base of ['.venv', 'venv']) {
    for (const sub of subDirs) {
      for (const name of names) {
        const p = path.join(baseDir, base, sub, name);
        if (fs.existsSync(p)) return p;
      }
    }
  }
  return isWindows ? 'python' : 'python3';
}
```

### 1.7 环境变量

优先用 `.env` 文件，不依赖系统环境变量的差异。

- Node.js：`dotenv` 或 Next.js 原生 `.env.local`
- Java：`application-{profile}.yml` + `${VAR:default}`
- Python：`pydantic-settings` 从 `.env` 读

### 1.8 字符编码

统一 UTF-8。

- Java：`pom.xml` 声明 `<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>`
- Python：Python 3 默认 UTF-8
- 文件读写：显式指定 `StandardCharsets.UTF_8` / `encoding='utf-8'`

## 二、代码风格

### Java

- 4 空格缩进
- 类名 PascalCase，方法名 camelCase，常量 UPPER_SNAKE_CASE
- 业务模块内部分层：controller / service / repository / entity / dto / converter
- DTO 用 `@Data` + `@Builder`（Lombok）

### Python

- 4 空格缩进，遵循 PEP 8
- 函数和变量 snake_case，类 PascalCase
- 用 `pathlib.Path` 而不是 `os.path`
- 类型注解（type hints）必写

### TypeScript / React

- 2 空格缩进
- 组件 PascalCase，函数 camelCase
- 每个组件一个文件，文件名 kebab-case
- 用 `'use client'` 显式标记客户端组件
- API 调用统一走 `lib/api/client.ts` 的 `request()`

## 三、Git 提交

### 提交信息格式

```
<type>: <简短描述>

<可选详细说明>
```

| type | 含义 |
|---|---|
| feat | 新功能 |
| fix | 修复 |
| refactor | 重构 |
| docs | 文档 |
| chore | 杂项（依赖、配置） |
| style | 格式调整 |
| test | 测试 |

示例：

```
feat: 新增文件批量删除
fix: 修复头像上传后不显示
docs: 新增跨平台开发规范
```

### 不提交的内容

`.gitignore` 已忽略：

- `node_modules/`、`.venv/`、`target/`、`.next/`
- `data/uploads/`
- `.env`、`.env.local`
- `.DS_Store`、`Thumbs.db`
- `*.docx`、`setup-*.js`

### 数据库迁移

- 改表结构必须新建 Flyway 迁移脚本
- 不允许手动 `ALTER TABLE`
- 脚本命名：`V{递增数字}__{描述}.sql`

## 四、接口设计

### URL 规范

- 全部小写 + 中划线：`/api/image-to-svg`、`/api/my-files`
- 资源复数：`/api/users`、`/api/files`
- 动词用 HTTP 方法表达：GET 查、POST 建、PATCH 改、DELETE 删

### 响应格式

```json
{ "code": 0, "message": "ok", "data": {} }
```

- `code = 0` 表示成功
- 非 0 是业务错误码（400 / 401 / 403 / 404 / 409 / 500）
- HTTP 状态码与 `code` 不完全对应（业务错误返回 HTTP 200，`code` 里体现）

### 鉴权

- Header：`Authorization: Bearer <token>`
- 未携带或失效：返回 `{"code":401,...}`
- 无权限：返回 `{"code":403,...}`

## 五、测试要求

### 修改后端接口

必须用 curl 测试 3 种情况：

1. 正常请求
2. 参数错误
3. 未登录 / 无权限

### 修改前端页面

必须测试：

1. 未登录访问 → 是否正确跳转
2. 登录访问 → 功能是否正常
3. 强制刷新（Cmd/Ctrl + Shift + R）→ 状态是否保留

## 六、双端互通检查清单

每次提交代码前，检查：

- [ ] 没有硬编码路径分隔符（`/` 或 `\`）
- [ ] 所有文件用 LF 换行
- [ ] 文件名全小写 + 中划线
- [ ] 脚本用 Node.js 编写（不是 `.sh` / `.bat`）
- [ ] 新增命令差异用 `isWindows` 判断
- [ ] 无平台特定的依赖（如 `pywin32`、`osx-only`）

## 七、反面案例

### 硬编码路径

```java
// 错误
Path p = Paths.get("data/uploads/image.png");

// 正确
Path p = Paths.get("data", "uploads", "image.png");
```

### 硬编码 venv 路径

```js
// 错误：Windows 上找不到
const py = path.join(root, '.venv', 'bin', 'python');

// 正确：动态检测
const py = findVenvPython(root);
```

### 用 shell 脚本做入口

| 错误 | 正确 |
|---|---|
| `scripts/start.sh` | `scripts/start.js` |
| `scripts/start.bat` | `scripts/start.js` |

### 大小写混用

| 错误 | 正确 |
|---|---|
| `components/Header.tsx` | `components/header.tsx` |
| `utils/ImageUtil.ts` | `utils/image-util.ts` |

### 平台特有命令

```js
// 错误：Windows 没有 rm -rf
execSync('rm -rf .next');

// 正确
fs.rmSync('.next', { recursive: true, force: true });
```

## 八、例外情况

| 场景 | 例外 |
|---|---|
| 一次性调试脚本 | 可以用 `.sh`，但不提交到仓库 |
| Dockerfile | 用 Linux 命令（容器本身是 Linux） |
| CI 配置 | GitHub Actions 用 Ubuntu |

原则：开发者需要在本地跑的东西，都必须双端兼容。
